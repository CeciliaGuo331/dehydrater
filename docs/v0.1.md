# dehydrater v0.1

第一个可用版本：命令行工具，把一节课的录音或录像（加上可选的 PDF 课件）整理成原始稿、脱水稿和以课件为主线的笔记。用法见 [README](../README.md)，架构与后续计划见 [design.md](design.md)。

## 功能

**输入**：一个带音轨的音视频文件（mp4、ts、mkv、mov、m4a、mp3、wav 等 FFmpeg 能解码的格式），加上零到多份 PDF 课件。

**输出**：

| 文件 | 内容 |
| --- | --- |
| `raw.md` | 语音识别原文，每句带时间 |
| `dehydrated.md` | 讲课全文精炼成书面文字，约为原文的四分之一，每段带时间 |
| `notes.md` | 以课件为主线、融入老师讲解的笔记：概览、课堂通知、按章组织的正文、术语表；出自讲解的内容标注录音时间 |

**命令行**：

- `dehydrater`：交互式整理，依次询问课堂名称、课堂资料、输出路径；支持 Tab 补全路径、含空格的路径、拖入文件
- `dehydrater setup`：逐项设置四个任务的接入地址、模型和 API Key，当场验证，并写入 shell 启动文件或配置目录
- `dehydrater process` / `status` / `check`：脚本用的非交互式整理、进度与用量查询、设置与连通性检查
- 进度按步骤实时显示；完成后列出各步骤的耗时、录音时长和 token 用量

**可靠性**：

- 断点续做：每个步骤及步骤内的每次模型调用都会缓存，中断或失败后重新运行只补做缺失的部分；改了配置或提示词只重做受影响的步骤
- 语音识别：开启 TCP keepalive，网络错误自动重试，报错时说明断在上传还是查询
- 日志：每节课的完整日志在 `cache/dehydrater.log`，全局日志在用户日志目录；不记录 API Key

## 处理流程

```text
录像/录音 ──► 提取音频 ──► 语音转写 ──┬──► raw.md
                                       │
                                       └──► 逐字稿脱水 ──┬──► dehydrated.md
                                                          │
课件 PDF ──► 读取课件 ────────────────────────────────────┴──► 笔记大纲 ──► 笔记撰写 ──► notes.md
```

| 步骤 | 做法 |
| --- | --- |
| 提取音频 | PyAV 解码，统一转成 16kHz 单声道 MP3（32kbps），2 小时约 29MB |
| 读取课件 | PyMuPDF 逐页抽取文字；多份课件按输入顺序统一编号 |
| 语音转写 | 火山引擎豆包语音「录音文件识别」标准版 2.0，音频以 base64 内联提交，轮询结果，分句时间戳精确到毫秒 |
| 逐字稿脱水 | 按约 2500 字分块并发调用大模型，把口语改写成书面文字、保留全部信息点 |
| 笔记大纲 | 一次读入全部课件和脱水稿，以课件结构分章，每章对应课件页码范围和讲课段落；同时生成概览、术语表、课堂通知 |
| 笔记撰写 | 按章并发撰写，以课件为主线，融入老师的解释、例子和强调的考点 |

**时间戳从不由模型生成**：模型只引用"第几句""第几段"，程序据此换算成录音时间。

## 验证结论

v0.1 的目标是回答四个问题，结论如下：

1. **语音识别准确率**：豆包录音文件识别 2.0 对中英混杂的课堂录音效果良好，`raw.md` 可以直接阅读。
2. **脱水会不会丢信息**：精炼改写后约为原文的四分之一，信息点保留完整。最初"只删口癖、不改写"的做法只压到原文的 77%，读起来仍然啰嗦，已改为精炼改写。
3. **笔记能否用于复习**：以课件为主线的笔记在多门课程上验证效果良好；能正确处理从课件中间开讲、跳讲、课件外插叙。课堂通知能抓到，偶尔混入老师的一般性提醒。
4. **耗时与用量**：2 小时的课约 15 分钟处理完。其中语音转写 9–11 分钟（上传约 2 分钟，服务端响应提交约 1.5 分钟，其余为识别）；大模型约 8 万输入 token、2 万输出 token。

## 已知限制

- **服务**：语音识别只支持火山引擎豆包语音（标准版）；大模型支持任何兼容 OpenAI Chat Completions 的服务
- **录音长度**：未核实火山对单个录音的时长上限，超过 2 小时的录音可能失败，也没有分段处理
- **课件**：只读取文字，图表等图片内容不进入笔记；不支持 PPTX，需先导出为 PDF
- **输出覆盖**：三份 `.md` 每次运行都会重新生成，手改前需另存
- **平台**：Linux、macOS、Windows 的 CI 均通过；`flake.nix` 的开发环境未在 NixOS 上验证；伪终端测试只在类 Unix 系统上运行
